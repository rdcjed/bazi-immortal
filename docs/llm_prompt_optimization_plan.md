## 一、现状分析

### 当前 prompt（`app.py` L197-231）

| 维度 | 现状 | 问题 |
|------|------|------|
| 角色类型 | 单条 user message | 无 system prompt，角色设定模糊 |
| 推理步骤 | 无（直接要求输出） | LLM 没有 step-by-step 推理引导 |
| 输出格式 | 简单 8 条编号列表 | 缺乏结构化，无表格/分节 |
| 知识库使用 | 截断到 300-400 字/文件 | 信息碎片化，不够充分 |
| 伦理边界 | 无 | LLM 可能输出绝对化结论 |
| token 限制 | 500字输出 + 1500 max_tokens | 太紧，无法输出完整分析 |
| 风格引导 | 仅"通俗但不失专业" | 无具体风格约束 |

### prompts/ 资源状态

`命运道士AI提示词.md` 包含：
- ✅ **角色设定**（云中子道士形象）

## 二、核心改动方案

### 改动 1：system prompt 加载

**做法：** 将 `prompts/命运道士AI提示词.md` 全文读入，作为 `system` role 传入 LLM。

```python
# app.py 新增
SYSTEM_PROMPT_PATH = os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "prompts", "命运道士AI提示词.md")

def load_system_prompt() -> str:
    """加载 System Prompt（带缓存）"""
    try:
        with open(SYSTEM_PROMPT_PATH, "r", encoding="utf-8") as f:
            return f.read()
    except Exception:
        # fallback: 一个简化的内置 system prompt
        return "你是一位精通子平八字的资深命理师——「云中子」。请基于命理逻辑推理计算，给出命理分析。"
```

**好处：** LLM 获得完整角色定义、推理链、输出模板、伦理约束，输出质量会系统性提升。

### 改动 2：API 调用改为 system + user 双消息

**当前调用：**
```python
messages = [{"role": "user", "content": prompt}]
```

**改为：**
```python
messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": user_prompt},
]
```

**user_prompt** 保持精简：只包含排盘引擎计算的 **结构化数据** + 用户问题。

### 改动 3：user prompt 重构成结构化数据提交

不再用自然语言描述命盘，改为明确的 Markdown 数据块：

```markdown
## 📊 排盘数据

| 维度 | 值 |
|------|-----|
| 出生 | 1990年5月15日 11:00 · 男 |
| 年柱 | 庚午 |
| 月柱 | 辛巳 |
| 日柱 | 甲子（甲日主） |
| 时柱 | 庚午 |
| 日主五行 | 木 |
| 身强弱 | 身弱 |
| 用神 | 水, 木 |
| 忌神 | 火, 土, 金 |
| 格局 | 正印格 |
| 大运方向 | 顺排，起运 3 岁 |
| 当前大运 | 丙戌（23-32岁） |
| 流年 | 2026 丙午 |

## 📂 知识库参考

[排盘引擎提供的相关片段...]
```

**核心原则：** system prompt 告诉 LLM **"怎么算"**，user prompt 告诉 LLM **"已经算好的数据是什么"**。LLM 不需要自己排盘，而是基于引擎结果做**综合解读和润色**。

### 改动 4：输出格式对齐模板

不再要求"1-8 编号列表"，改为让 LLM 自然遵循 system prompt 中的输出模板：

| 模板段落 | 说明 |
|----------|------|
| 📇 八字排盘 | 表格展示四柱 |
| 🌟 命局总评 | 一句话总评 + 推理依据 |
| 💼 事业运势 | 十神配置 + 日主强弱 → 工作类型 |
| 💰 财运分析 | 财星旺衰 + 身强身弱 → 财大小 |
| ❤️ 感情/婚姻 | 男财女官 + 夫妻宫 + 桃花 |
| 🏥 健康注意 | 五行过旺/过弱对应脏腑 |
| 📅 当前流年运势 | 流年干支 + 大运 × 流年互动 |
| 🎯 具体建议 | 3-5 条可操作建议 |

同时保持 **伦理边界约束**：
- 不承诺 100% 准确
- 不鼓励迷信
- 使用"趋势上"、"可能性"、"需要注意"等措辞

### 改动 5：放宽 token 限制

| 参数 | 当前值 | 建议值 |
|------|--------|--------|
| output 字数限制 | 500字 | 800-1200字 |
| max_tokens | 1500 | 2500 |
| temperature | 0.5 | 0.5（保持稳定） |

### 改动 6：知识库上下文增强

当前只取了 4 个文件中各 400 字，太碎片化。改为：

1. **按需要动态选择**：根据日主五行选择对应章节（已有，保留）
2. **增大截断长度**：400 → 1200 字符/文件
3. **添加关键文件**：增加 `07_穷通宝鉴精要.md` 和 `10_命运推理进阶逻辑.md`
4. **格式标准化**：`## {文件名}\n{content[:1200]}\n`

### 改动 7：保留并优化 fallback 机制

| 路径 | 条件 | 行为 |
|------|------|------|
| **A → B** | LLM 调用成功 | 返回 LLM 分析结果 + 排盘数据 |
| **A → C** | LLM 调用失败（网络/API key） | 回退到规则引擎 |
| **A → D** | LLM 返回空/异常 | 回退到规则引擎 |
| **E** | 二次润色（可选） | 规则引擎结果 → LLM 润色（保留现有逻辑） |

### 改动 8：前端渲染适配

当前 `templates/index.html`（L394-416）已有 `result.llm.llm_analysis` 渲染，只需调整 CSS 以更好展示 LLM 输出的结构化内容（标题、表格、列表）：

1. 表格自动适配暗色风格
2. 标题加粗高亮
3. 保持 `white-space: pre-wrap` 以保留 LLM 的换行格式

## 五、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| system prompt 太长（465行） | token 消耗增大 | user prompt 精简到 300-500 字，整体控制在 4000 tokens 以内（system 约 2500 + user 约 500 + output 2500）|
| LLM 可能偏题 | 输出质量下降 | system prompt 有明确步骤链约束 |
| 知识库容量增大 | API 成本略增 | 1200 字 × 6 文件 ≈ 7200 字 ≈ 1800 tokens，可接受 |
| fallback 路径不变 | 无风险 | 保持现有 fallback 逻辑 |
